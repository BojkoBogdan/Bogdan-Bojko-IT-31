# Практика 13. Створення індексів та аналіз ефективності запитів

*Мета заняття: застосувати `CREATE INDEX` і `EXPLAIN QUERY PLAN` з
Лекції 15 до своєї бази — побудувати індекс на фактовій таблиці й на
власні очі побачити зміну плану виконання запиту з `SCAN` на
`SEARCH USING INDEX`.*

## Заготовка вашого варіанта (файл `.sql`)

Ця практика — **схемо-змінна**: вона додає новий елемент структури
бази (індекс), тож, за тим самим принципом, що і в Практиці 4, нижче —
готовий файл стану **перед** цією практикою для кожного з 10
варіантів. На відміну від файлів Практики 4 (лише таблиця-вимір 1),
цей файл відтворює вже ПОВНУ схему з усіма трьома таблицями й
зовнішніми ключами (те, що мало вийти в результаті Практики 4) —
і трохи більший набір реалістичних рядків (12 у кожній таблиці-вимірі,
20 у фактовій), щоб порівняння `SCAN`/`SEARCH` було наочнішим. Індексу
в жодному з файлів немає навмисно — його побудова і є завданням цієї
практики:

- [v1_prerequisites.sql](sql/13-indexes/v1_prerequisites.sql) — Бібліотека
- [v2_prerequisites.sql](sql/13-indexes/v2_prerequisites.sql) — Інтернет-магазин одягу

- [v4_prerequisites.sql](sql/13-indexes/v4_prerequisites.sql) — Аптека
- [v5_prerequisites.sql](sql/13-indexes/v5_prerequisites.sql) — Автосалон
- [v6_prerequisites.sql](sql/13-indexes/v6_prerequisites.sql) — Готель
- [v7_prerequisites.sql](sql/13-indexes/v7_prerequisites.sql) — Спортзал (фітнес-клуб)
- [v8_prerequisites.sql](sql/13-indexes/v8_prerequisites.sql) — Служба доставки їжі

Якщо власна база з попередніх практик збережена й робоча — можете
продовжувати працювати з нею (вона вже містить усі потрібні таблиці й
дані); файл вище потрібен лише якщо базу втрачено чи хочете почати
цю практику на "чистому", більшому наборі даних. Виконайте:
`sqlite3 назва_файлу.db < v3_prerequisites.sql` (CLI) або
**Execute SQL** у DB Browser for SQLite.

## Приклад: наскрізна демонстрація

```sql
-- план ДО індексу
EXPLAIN QUERY PLAN
SELECT * FROM visits WHERE vet_id = 2;
-- SCAN visits

CREATE INDEX idx_visits_vet ON visits(vet_id);

-- план ПІСЛЯ індексу
EXPLAIN QUERY PLAN
SELECT * FROM visits WHERE vet_id = 2;
-- SEARCH visits USING INDEX idx_visits_vet (vet_id=?)
```

## Завдання

**Завдання 1. EXPLAIN QUERY PLAN до індексу.** Виконайте
`EXPLAIN QUERY PLAN` для запиту, що фільтрує вашу фактову таблицю за
одним із зовнішніх ключів (`WHERE product_id = ...`,
`WHERE customer_id = ...` тощо). Зафіксуйте письмово точний текст
плану, який показала SQLite, ДО створення будь-якого індексу.

**Завдання 2. CREATE INDEX на зовнішньому ключі.** Створіть індекс на
тому самому зовнішньому ключі фактової таблиці, який використали в
Завданні 1. Повторіть той самий `EXPLAIN QUERY PLAN`-запит і зафіксуйте
письмово, як саме змінився текст плану.

**Завдання 3. Композитний індекс.** Побудуйте запит, що фільтрує
фактову таблицю за **двома** умовами одночасно (наприклад,
`WHERE customer_id = ... AND status = ...`). Виконайте
`EXPLAIN QUERY PLAN` для нього до й після створення композитного
індексу на обох колонках (`CREATE INDEX ... ON таблиця(колонка1,
колонка2)`). Письмово поясніть різницю в плані.

**Завдання 4. Індекс і ORDER BY.** Побудуйте індекс на колонці-даті
вашої фактової таблиці (`order_date`, `sale_date`, `trip_date` тощо) і
порівняйте `EXPLAIN QUERY PLAN` для запиту з `ORDER BY` за цією
колонкою — до й після створення індексу. Письмово поясніть, що саме
змінилось у плані щодо кроку сортування.

**Завдання 5. DROP INDEX і повторна перевірка.** Видаліть один зі
створених індексів (`DROP INDEX`) і повторіть відповідний
`EXPLAIN QUERY PLAN`-запит. Письмово підтвердьте: план повернувся до
`SCAN` (чи використовує інший з наявних індексів, якщо такий
покриває запит частково) — і перевірте окремим `SELECT` із
`sqlite_master`, що індекс справді видалено зі списку.

## Що здати й оцінюється

Здайте текст усіх виконаних команд (`CREATE INDEX`, `DROP INDEX`,
`EXPLAIN QUERY PLAN`) разом з точними текстами планів до й після для
Завдань 1-5, і письмові пояснення до Завдань 2-5. Контрольні питання:

- Чому `EXPLAIN QUERY PLAN` показує саме ПЛАН, а не результат запиту —
  і навіщо перевіряти план окремо від того, що запит просто "працює"?
- У Завданні 3 — чому індекс лише на першій із двох колонок умови дає
  менший ефект, ніж композитний індекс на обох?
- Яка ціна створення індексу (Лекція 15, розділ 6), і чому не варто
  індексувати кожну колонку таблиці "про всяк випадок"?

Оцінюється точність зафіксованих текстів плану до/після в кожному
завданні, правильний вибір колонок для індексу (Завдання 2-4), і
розуміння того, коли композитний індекс дає перевагу над одноколонковим
(Завдання 3).

## Підсумок заняття

- Побудовано індекс (одноколонковий і композитний) на фактовій таблиці
  свого варіанта та підтверджено зміну плану виконання запиту з `SCAN`
  на `SEARCH USING INDEX`.
- На практиці підтверджено вплив індексу на `ORDER BY` та перевірено
  видалення індексу через `DROP INDEX` і `sqlite_master`.
- Зафіксовано усвідомлення того, що індекс має свою ціну і створюється
  цілеспрямовано, а не на кожній колонці підряд.
